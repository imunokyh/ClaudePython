## 1. 테스트 명세 개요

`system-test-case-designer` 서브 에이전트(`system-test-case-generator` 스킬)로 SW 요구사항 명세에서 도출했다. 스킬 검증 스크립트(`build_workbook.py`)를 오류 0건으로 통과했다.

| 항목 | 값 |
|---|---|
| 테스트 베이시스 항목 | 22 (기능 18, 비기능 4) |
| 베이시스 커버리지 | 22/22 (100%), TC → 베이시스 추적성 100% |
| 테스트 케이스 | 202 (기능 168, 비기능 34 / 기본 198, 제안 4) |
| 기법 (복수 표기) | 동치 클래스 175, 결정 테이블 55, 페어와이즈(PICT) 45, WoW 검증 40, 상태 전이 30, 경계값 분석 27, 결함 주입 26, 오류 추측 6, 요구사항 기반 5 |

부록 A 결정표(D-01~45, P-01~10) 55행은 행마다 1건씩 케이스로 만들었다.

### 2.1 발견 사항

| ID | 분류 | 영향 케이스 | 내용 | 처리 |
|---|---|---|---|---|
| F-01 | 시험 케이스 결함 | FTC-151, FTC-D-40~42, FTC-P-07, FTC-PW02-2~7 (11건) | 케이스가 `priority_reason`을 `fire`/`overtemperature`로 기대했다. SWE1-SRS 1.4절 순위 7은 `fire_detected`/`overtemperature_detected`로 정의하며 제품은 요구사항대로 동작한다 | 케이스 기대값을 요구사항 문구대로 정정 |
| F-02 | 요구사항 결함 | FTC-154, NTC-201~212, 214, 216, 231 (16건) | SWR-015 수용기준이 "범위 밖 값을 보내면 200"이었으나, 상세 설계(SWE3-DD 6장)·구현·통합 시험(IT-05)은 처음부터 202(Accepted)였다. 입력은 우편함에 접수만 하고 평가는 다음 주기에 하므로 202가 맞는 의미다 | 요구사항 개정(SWE1-SRS 1.3)으로 202로 정정하고 케이스를 맞춤. SWE.1 → SWE.6까지 요구사항과 설계의 불일치가 남아 있었던 것은 추적 검토의 누락이다 |
| F-03 | 시험 케이스 결함 | NTC-232 (불합격은 아님) | 절차의 시각 표기(13.95, 14.00 s)가 "0.05 s 간격 99회"와 맞지 않아 그대로 따르면 평가 시각 역행이 된다 | 절차를 14.95, 15.00 s로 정정 |

케이스 기대값 정정은 작성자(개발 측)가 했다. 정정마다 근거가 되는 요구사항 문구나 개정 이력을 위 표에 남겼다.

### 2.2 보류 항목과 다른 수준에서의 검증

| 질의 | 내용 | 검증 위치 | 판정 |

| ST Q-01 | SWR-015 "응답 직렬화 실패 시 HTTP 500": PC/SIL HTTP 경로로는 직렬화 실패를 주입할 수 없다 | 단위 시험 `tests/unit/test_web.py::test_serialization_failure_returns_500` (`/status`, `/events`, `/clock` 모두 500) | 단위 수준에서 검증 |

## 3. 추적

- SWR → TC: `system-test-spec.xlsx`의 "추적성 매트릭스" 시트 (22/22).
- TC → 자동 시험: 시험 함수 이름과 docstring 첫 줄에 tc_id, basis_ids를 적었다 (`tests/system/test_st_*.py`, 결정표·PICT는 `parametrize` id).
- 단위·통합 수준 검증과의 연결: 2.2절.

## 5. 잔여 문제

| 구분 | 내용 | 상태 |
|---|---|---|
| OEM 질의 | SWE1-QRY Q-01~Q-13 (규칙 간 우선순위, 평가주기, PENDING 처리, freshness 등). 현재 결과는 공급자 가정 A-01~A-25 기준이다. 특히 Q-01b(화재 시 접근위험 쪽 해제 여부)는 안전 판단이 필요하다 | 답변 대기. 답변이 가정과 다르면 해당 SWR·설계·시험을 갱신 |

| 시험 소요 시간 | SWE.6 자동 시험 약 150초 (대부분 NTC-234 1,000회 재생과 실제 대기) | 허용. 전체 대기 실행은 `ST_FULL_WALL_WAIT=1` |

## 6. 결론

테스트 베이시스 SWR-001~022에 대해 PC/SIL 범위에서 202건을 모두 합격했다. 보류 2항목은 단위·통합 수준에서 기능을 검증했다. 제품 코드 결함은 발견되지 않았고, 요구사항 결함 1건(F-02)과 시험 케이스 결함 2건(F-01, F-03)을 정정했다. OEM 질의 답변 전까지 결과는 공급자 가정 기준이다.
